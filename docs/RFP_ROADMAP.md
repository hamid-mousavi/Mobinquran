## ۰. راهنمای استفاده از این سند (برای انسان و AI)

**روش کار پیشنهادی:**

1. در ابتدای هر جلسهٔ کاری با AI، «پرامپت زمینهٔ ثابت» (پیوست ب) را می‌چسبانید.
2. سپس پرامپت همان فاز را (انتهای هر فاز) می‌دهید. فقط **یک فاز** در هر مرحله.
3. AI باید اول **طرح** بدهد، بعد پس از تأیید شما پیاده‌سازی کند (کامیت‌های کوچک، با تست).
4. بعد از هر فاز، «معیار پذیرش» همان فاز را خودتان چک کنید و بعد سراغ فاز بعد بروید.

**قواعد ثابت برای AI (در همهٔ فازها):**

- هیچ متن قرآنی، ترجمه، تفسیر یا حدیثی را از حافظهٔ مدل تولید یا «اصلاح» نکن. فقط از دادهٔ منبع‌دار داخل پروژه استفاده کن.
- متن قرآن باید بی‌تغییر از منبع بیاید و با تست تعداد (۶۲۳۶ آیه، ۱۱۴ سوره، ۶۰۴ صفحه، ۳۰ جزء) اعتبارسنجی شود.
- هیچ کلید API در کد کلاینت یا مخزن نباشد.
- هیچ وابستگی زمان‌اجرا به CDN خارجی (فونت، اسکریپت، آیکن) نباشد؛ کاربران ایران ممکن است به آن‌ها دسترسی نداشته باشند.
- هر تغییر ساختار دیتابیس با migration نسخه‌دار Dexie انجام شود.
- کد موجود را بازنویسی کلی نکن؛ تغییرات تدریجی و قابل‌بازگشت.
- اگر اطلاعاتی نداری (مجوز، ساختار API، شناسهٔ edition)، حدس نزن؛ سؤال بپرس یا در `docs/OPEN_QUESTIONS.md` ثبت کن.

**برچسب‌های تخمین زمان:** S ≈ ۲–۴ ساعت · M ≈ ۶–۱۲ ساعت · L ≈ ۱۵–۳۰ ساعت (تخمین برای یک توسعه‌دهنده به کمک AI)

# بخش الف — RFP

## ۲. هدف و چشم‌انداز

تبدیل «قرآن مبین» به یک اپ قرآنی **قابل اعتماد، آفلاین‌محور، سبک و رایگان** برای قرائت، تدبر، حفظ و پیگیری مستمر ختم، با هدف صدقهٔ جاریه.

**اصول محصول:**

1. **اصالت قبل از قابلیت:** چیزی که منبع معتبر ندارد نمایش داده نمی‌شود.
2. **آفلاین‌ اول:** هستهٔ قرائت باید بدون اینترنت کار کند، از اولین اجرا.
3. **AI اختیاری و مستند:** اپ بدون AI هم کامل است. AI فقط به آیات و منابع ارجاع می‌دهد و نقش مفتی یا مشاور ندارد.
4. **حریم خصوصی:** بدون حساب کاربری اجباری؛ داده‌ها روی دستگاه.
5. **سبک برای دستگاه‌های ضعیف و اینترنت ضعیف/فیلترشده.**

## ۳. دامنه

**در دامنه:** قرائت (آیه‌به‌آیه + مصحف)، جستجو، ترجمه‌ها، بسته‌های محتوایی (ترجمه/تفسیر/ادبیات)، صوت آفلاین، حفظ، ختم، بوکمارک/یادداشت، بکاپ، دستیار AI مستند، انتشار PWA + اندروید (بازار/مایکت).

**خارج از دامنه (فعلاً):** حساب کاربری و همگام‌سازی ابری، شبکهٔ اجتماعی/انجمن، پرداخت و تبلیغات، iOS بومی، ترجمهٔ خودکار محتوا با AI، تولید تفسیر توسط AI به‌عنوان «تفسیر رسمی».

## ۵. محدودیت‌ها و فرض‌ها

- **جغرافیا:** کاربران در ایران. دسترسی به سرویس‌های خارجی (Vercel، Groq، Gemini، Sentry، CDNها، Google Fonts) ممکن است مختل یا فیلتر باشد؛ معماری باید با قطعی آن‌ها زنده بماند.
- **توسعه‌دهنده:** تک‌نفره، زمان محدود؛ هر فاز کوچک و مستقل تحویل‌پذیر باشد.
- **بودجه:** صفر/حداقل. فقط سهمیهٔ رایگان سرویس‌ها؛ سقف مصرف AI الزامی است.
- **مجوز:** فعلاً مجوزی برای تفسیرهای نمونه/المیزان و ترجمه‌ها نیست؛ پس آن‌ها در محصول نباشند مگر پس از اخذ مجوز.
- **مذهب:** شیعی‌محور، با معماری بسته‌های محتوایی برای افزودن تفاسیر اهل سنت در آینده.
- **بک‌اند فعلی:** `app.ts` (Express) روی Vercel Serverless.

## ۸. سیاست محتوا و مجوز

1. **متن قرآن:** بدون هیچ تغییر، با انتساب به منبع. شرایط استفادهٔ منبع (مثلاً Tanzil یا مجمع ملک فهد) قبل از انتشار خوانده و در manifest ثبت شود.
2. **ترجمه‌ها:** مجوز هر ترجمه جداگانه بررسی شود. ترجمه‌ای که مجوز روشن ندارد به‌صورت پیش‌فرض در اپ ارسال نشود؛ فقط «دانلود اختیاری از منبع اصلی» یا حذف.
3. **تفسیرهای نمونه/المیزان/مجمع‌البیان/نور:** تا اخذ مجوز مکتوب، **کپی و بازنشر نشود**. جایگزین: لینک عمیق به وب‌سایت رسمی ناشر/مرکز نور (بدون scraping) و درخواست مجوز.
4. **صوت:** فقط منابعی که شرایط استفاده‌شان اجازه می‌دهد. ترجیحاً پخش از منبع اصلی با ذکر نام قاری/منبع؛ کش‌کردن برای پخش آفلاین کاربر پس از بررسی شرایط.
5. **داده‌های ادبی/صرفی (مثلاً corpus عربی قرآن):** مجوز (مثلاً GPL) قبل از ادغام بررسی و پیامد آن روی مجوز اپ ثبت شود.
6. **کد:** پیشنهاد می‌شود اپ متن‌باز شود (مثلاً MIT/Apache برای کد؛ محتوا با مجوز جداگانه). برای صدقهٔ جاریه و جذب مشارکت‌کننده مناسب است؛ تصمیم با شماست.
7. **شفافیت:** هر محتوا در UI با «منبع + مترجم/مؤلف + نسخه» قابل مشاهده باشد.

## ۹. سیاست هوش مصنوعی

**اصول:**

- AI **توضیح‌دهنده و مسیرنما** است، نه مرجع دینی. پاسخ همیشه به آیه و منبع ارجاع دارد.
- **متن آیه هرگز از خروجی مدل نمایش داده نمی‌شود.** مدل فقط شناسهٔ آیه (مثل `94:5`) برمی‌گرداند؛ برنامه متن را از دیتابیس محلی می‌آورد و وجود شناسه را اعتبارسنجی می‌کند.
- ادعای «تفسیر X می‌گوید» فقط زمانی مجاز است که متن همان تفسیر در زمینهٔ پرامپت (RAG) داده شده باشد.

**رفتارهای ممنوع/محدود:** صدور فتوای فقهی؛ تشخیص یا درمان پزشکی/روانی؛ تفسیر به رأی قطعی برای مسائل اختلافی؛ جدل و تکفیر؛ نقل حدیث بدون منبع.

**موقعیت بحران:** اگر متن پرسش حاوی نشانه‌های آسیب به خود یا دیگران بود، پاسخ باید همدلانه باشد و به کمک حرفه‌ای (مشاوره/اورژانس اجتماعی) ارجاع دهد. شمارهٔ رسمی مراکز پیش از انتشار تأیید و در پیکربندی قرار گیرد.

**کنترل هزینه و سوءاستفاده:** rate limit بر اساس IP و شناسهٔ دستگاه، سقف روزانه، سقف طول ورودی/خروجی، کلید kill-switch، لاگ توکن (نه متن)، و حالت بدون AI (fallback محلی).

**دسترسی از ایران:** کلاینت فقط با بک‌اند شما صحبت می‌کند؛ بک‌اند با provider. تست دسترسی از ایران هم برای دامنهٔ بک‌اند و هم برای provider و پرداخت/سهمیهٔ رایگان لازم است (بند ۱۰).

## فاز ۶ — هوش مصنوعی مستند و امن (RAG) (≈ ۲۰–۴۰ ساعت)

**هدف:** پاسخ‌های AI که همیشه به آیات واقعی و منبع ارجاع می‌دهند و هزینهٔ کنترل‌شده دارند.

**پیش‌نیاز:** P0-T2 و P0-T5 انجام شده باشند (حذف اسناد جعلی و سخت‌سازی endpoint). در نسخهٔ نهایی «ایجنت‌های» منتسب به مفسران وجود نداشته باشند؛ فقط یک دستیار با رویکرد انتخابی.

**معماری (خلاصه):**

```
کاربر → (کلاینت) جستجوی محلی + گسترش کلیدواژه → ≤ ۱۲ آیهٔ کاندید
      → POST /api/ai/ask { question, candidates:[{ref, text_fa}], lang }
      → (سرور) اعتبارسنجی، rate limit، provider، prompt سیستم v2
      → JSON ساخت‌یافته { verses:[{ref, why, practical_note}], summary, confidence, ... }
      → (کلاینت) اعتبارسنجی ref‌ها با Dexie، نمایش متن آیه از دیتابیس، نمایش منبع/هشدار
```

**قرارداد پاسخ (نمونه):**

```json
{
  "language": "fa",
  "summary": "خلاصهٔ کوتاه و محتاطانه",
  "verses": [
    { "ref": "94:5", "why_relevant": "…", "practical_note": "…" }
  ],
  "tafsir_citations": [],
  "confidence": "high | medium | low",
  "needs_human_scholar": false,
  "disclaimers": ["تولیدشده با هوش مصنوعی؛ ممکن است خطا داشته باشد."]
}
```

قواعد: `ref` فقط از میان کاندیدهای ارسال‌شده؛ `tafsir_citations` خالی مگر متن آن تفسیر در زمینه بوده؛ ساختار نامعتبر ← یک بار تلاش برای اصلاح ← در غیر این صورت نمایش نتایج جستجوی محلی.

**وظایف:**

- [ ] **P6-T1 (M)** بازسازی بک‌اند: zod، شناسهٔ درخواست، rate limit پایدار (KV/Redis/SQLite) بر اساس IP + شناسهٔ دستگاه، سقف روزانه، محدودیت ورودی/خروجی، timeout، عدم ذخیرهٔ متن پرسش (فقط توکن/متریک)، Turnstile یا اثبات کار (اختیاری)، kill-switch.

## فاز ۷ — تفسیر و ادبیات واقعی (Content Packs) (≈ ۱۵–۴۰ ساعت؛ وابسته به مجوز)

**هدف:** تفسیر و صرف/نحوی که واقعاً منبع‌دار است؛ آماده برای منابع شیعه و اهل سنت.

**قالب بستهٔ تفسیر:**

```ts
interface TafsirPackManifest {
  id: string;                       // مثلاً 'tafsir-almizan-fa'
  madhab: 'imamiyyah' | 'sunni' | 'neutral';
  title: string; author: string;
  language: 'fa' | 'ar' | 'en';
  license: string; licenseUrl?: string;
  attribution: string; sourceUrl: string;
  version: string; checksum: string; sizeBytes: number;
}
interface TafsirEntry {
  packId: string; surahId: number;
  fromAyah: number; toAyah: number;
  text: string;
  citation?: { volume?: number; page?: number; note?: string };
}
```

**وظایف:**

- [ ] **P7-T1 (M)** موتور Content Pack: نصب/حذف/به‌روزرسانی، اعتبارسنجی checksum و schema، نمایش مذهب/مجوز/نسخه، ذخیره در Dexie، جستجو در پک.
- [ ] **P7-T2 (S)** UI تفسیر: انتخاب بسته، برچسب مذهب، منبع، جلد/صفحه، دکمهٔ «گزارش اشکال»؛ **نمایش تب فقط اگر حداقل یک بسته نصب باشد**.
- [ ] **P7-T3 (L، وابسته به مجوز)** منابع شیعه: تفسیر نمونه، المیزان، مجمع‌البیان، نور. مسیر ۱: اخذ مجوز مکتوب از ناشر/مرکز نور. مسیر ۲ تا حصول مجوز: **لینک عمیق** به سایت رسمی ناشر (بدون scraping/کپی).
- [ ] **P7-T4 (L، وابسته به مجوز)** منابع اهل سنت (آینده): مثلاً ابن‌کثیر، جلالین، سعدی، میسّر، طبری، قرطبی. قبل از استفاده، مجوز و منشأ دیجیتال هر نسخه بررسی شود (متن اصلی قدیمی است ولی نسخهٔ دیجیتال ممکن است حقوق داشته باشد).
- [ ] **P7-T5 (L)** صرف/نحو/ریشه: دادهٔ کلمه‌به‌کلمه از منبع واقعی (مثلاً Quranic Arabic Corpus یا QUL؛ مجوز، مثلاً GPL، بررسی شود)، جدول `words`، نمایش ریشه، قالب، نقش نحوی و ترجمهٔ کلمه.
- [ ] **P7-T6 (M)** شأن نزول از منبع مستند (مثلاً واحدی و ترجمه‌های مجاز) به‌صورت بسته.
- [ ] **P7-T7 (S)** اتصال به AI (فاز ۶): وقتی بسته نصب است، بخش مربوط به همان آیه به‌عنوان زمینهٔ RAG به مدل داده شود و ارجاع مطابق آن ثبت شود (FR-AI-09).

**معیار پذیرش:** هیچ متن تفسیری بدون بسته/منبع/مجوز نمایش داده نمی‌شود؛ افزودن یک بستهٔ اهل سنت فقط با افزودن manifest+داده و بدون تغییر کد اصلی ممکن است.

**پرامپت:**
```

```
