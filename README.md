# قرآن مبین (Quran Mobin)

نرم‌افزار جامع، مدرن و آفلاین قرآن کریم مبتنی بر استاندارد Progressive Web App (PWA) و React/Vite.

---

## قابلیت‌های کلیدی

- **داده‌های استاندارد و آفلاین:** شامل تمامی ۶٬۲۳۶ آیه قرآن کریم در ۱۱۴ سوره، ۳۰ جزء و ۶۰۴ صفحه مصحف عثمانی به همراه ۳ ترجمه رسمی فارسی (آیت‌الله مکارم شیرازی، استاد فولادوند، استاد انصاریان) مستقر در بسته داخلی `quran-core-v1.json` بدون نیاز به دسترسی به اینترنت در زمان اجرا.
- **مصحف ۱۵ خطی مدینه:** شبیه‌سازی دقیق چیدمان صفحات عثمانی با تفکیک کلمه به کلمه و فونت‌های استاندارد قرآنی.
- **جستجوی سریع:** جستجوی هوشمند در متن اعراب‌گذاری‌شده، املای ساده بدون اعراب و ترجمه‌های فارسی با نرمال‌سازی حروف.
- **دستیار هوشمند تدبّر و ارزیابی قرائت:** مجهز به موتور هوش مصنوعی با اعتبارسنجی ساختار خروجی و لایه‌های سخت‌سازی امنیتی، کنترل سهمیه روزانه و ایزولاسیون کلیدهای API سمت سرور.
- **اوقات شرعی:** محاسبه دقیق اوقات شرعی شهرها و قبله‌نما.
- **حفظ حریم خصوصی:** بدون تبلیغات، بدون رهگیری و با ذخیره‌سازی محلی نشانه‌ها، یادداشت‌ها و تنظیمات کاربر در IndexedDB مرورگر.

## اجرای محلی (Local Development)

پیش‌نیازها: **Node.js** نسخه ۱۸ به بالا و **npm**.

۱. نصب وابستگی‌ها:
```bash
npm install
```

۲. تنظیم متغیرهای محیطی در `.env.local` (نمونه در `.env.example` قرار دارد):
```bash
GEMINI_API_KEY=your_gemini_api_key_here
PUBLIC_APP_URL=http://localhost:3000
ALLOW_MEMORY_RATE_LIMIT=true
```

۳. اجرای سرور توسعه:
```bash
npm run dev
```
برنامه روی آدرس `http://localhost:3000` در دسترس خواهد بود.

## متغیرهای محیطی (Environment Variables)

تمام کلیدها منحصراً در سمت سرور پردازش می‌شوند و هیچ متغیری با پیشوند `VITE_` حاوی کلیدهای محرمانه نیست:

| متغیر | ضرورت | توضیح |
|---|---|---|
| `GEMINI_API_KEY` | اصلی | کلید دسترسی به سرویس هوش مصنوعی گوگل برای دستیار تدبّر و آزمون تلاوت. |
| `GROQ_API_KEY` | اختیاری | کلید ارائه‌دهنده جایگزین Groq جهت fallback در صورت قطعی سرویس اصلی. |
| `DEEPSEEK_API_KEY` | اختیاری | کلید ارائه‌دهنده جایگزین DeepSeek. |
| `OPENROUTER_API_KEY` | اختیاری | کلید ارائه‌دهنده جایگزین OpenRouter. |
| `UPSTASH_REDIS_REST_URL` | استقرار ابری | نشانی REST دیتابیس Upstash Redis جهت اعمال نرخ محدودیت سهمیه روزانه در استقرار سرورلس. |
| `UPSTASH_REDIS_REST_TOKEN` | استقرار ابری | توکن احراز هویت Upstash Redis. |
| `ALLOW_MEMORY_RATE_LIMIT` | محلی/تست | مقدار `true` اجازه می‌دهد در صورت عدم پیکربندی ردیس، از کش حافظه محلی برای سهمیه‌بندی استفاده شود. |
| `PUBLIC_APP_URL` | اختیاری | دامنه عمومی اپلیکیشن (برای تنظیم هدرهای CORS و ارجاعات OpenRouter). |
| `AI_DAILY_LIMIT` | اختیاری | سقف تعداد پرسش گفتگوی هوش مصنوعی در هر شبانه‌روز برای هر شناسه دستگاه (پیش‌فرض: ۲۰). |
| `AI_HELP_DAILY_LIMIT` | اختیاری | سقف جداگانهٔ «کمک هوشمند حفظ» برای آیه‌های پرخطا در هر شبانه‌روز (پیش‌فرض: ۱۵). |
| `AI_RECITATION_DAILY_LIMIT` | اختیاری | سقف جداگانهٔ «داوری تلاوت با هوش مصنوعی» در هر شبانه‌روز برای هر شناسه دستگاه (پیش‌فرض: ۳۰). مصرف آن از سهمیهٔ گفتگو کم نمی‌شود. |

## استقرار روی Vercel (Deploy on Vercel)

پروژه برای استقرار پایدار در بسترهای ابری و Vercel معماری شده است:
- فرانت‌اند اپلیکیشن با دستور `vite build` در پوشه `dist/` کامپایل می‌شود.
- رابط‌های برنامه‌نویسی سمت سرور (`/api/*`) از طریق `server/serverless.ts` با ابزار esbuild به خروجی توابع سرورلس استاندارد (`api/index.js` و `api/[...path].js`) تبدیل می‌گردند.
- هدرهای امنیتی، ریرایت‌های SPA و قوانین کش در `vercel.json` پیکربندی شده‌اند.

مراحل استقرار:
1. پروژه را به گیت‌هاب متصل کنید و مخزن را در Vercel اضافه نمایید.
2. در تنظیمات پروژه در Vercel: **Settings → Environment Variables**، متغیر `GEMINI_API_KEY` و سایر متغیرهای مورد نیاز (مانند ردیس Upstash) را اضافه کنید.
3. بیلد پروژه را اجرا کنید؛ فرمان ساخت `npm run build` به طور خودکار هر دو بخش فرانت‌اند و توابع سرورلس را تولید می‌کند.

## نسخهٔ بومی اندروید (Android with Capacitor)

پروژه به همراه بستر بومی اندروید با استفاده از `@capacitor/core` و شناسه بستهٔ یکتای `app.vercel.mobinquran.twa` پیکربندی شده است.

### دستورات توسعه و بیلد اندروید

```bash
# بیلد وب و انتقال به پروژه اندروید
npm run build:android

# باز کردن پروژه در Android Studio
npm run open:android
```

### ساخت نسخهٔ نهایی امضاشده (Signed AAB / APK) در Android Studio

1. دستور `npm run build:android` را اجرا کنید.
2. با دستور `npm run open:android`، پروژه در نرم‌افزار Android Studio باز می‌شود.
3. از منوی بالا به مسیر **Build → Generate Signed Bundle / APK** بروید.
4. گزینه **Android App Bundle (AAB)** را انتخاب کنید (الزامی برای بارگذاری در گوگل‌پلی).
5. کلید امضای موجود (`keystore`) مربوط به نسخه قبلی TWA را انتخاب و گذرواژه‌های آن را وارد نمایید.
6. حالت **Release** را انتخاب و گزینه **Finish** را بزنید تا فایل `.aab` در مسیر `android/app/release/` تولید گردد.
